# Story 006：計算引擎（交易紀錄 → 持股與報酬）

**身為** 分批買賣、也會領股利的長期投資人
**我想要** App 依我記下的每一筆交易與股利，算出持股、平均成本、已實現與未實現損益、總報酬
**以便** 看到的賺賠數字和券商對帳單一致，不會因為漏算手續費、稅或股利而算錯錢

這張 story 只做**計算引擎**（`src/domain/` 的純函式），沒有畫面也沒有儲存；畫面在 Story 009 之後接上。
規則全部來自 [product-spec.md](../product-spec.md) 第 3 章與第 4 章，以及 M-02、M-03、M-09 中和計算有關的 AC。名詞見 [glossary.md](../glossary.md)。

## 決策紀錄

規格沒寫到、或需要選做法的地方。原則：選最不會讓使用者算錯錢的做法。

1. **浮點數**：規格 3.1 建議 decimal 函式庫或以「分」為單位；這裡照實作指南用一般 `number` 保留完整精度，手續費與證交稅一律經過 `floorMoney(x) = Math.floor(x + 1e-9)` 取整，避免 `56.99999999999999` 這類誤差少算 1 元。不加套件。
2. **賣出成本**用 `持有成本 × 賣出股數 ÷ 持有股數` 計算（數學上等於「平均成本 × 賣出股數」），少一次除法誤差；**全部賣光時持有成本直接歸零**，不留 0.0000001 的殘值。
3. **最低手續費看單筆股數**：股數 ≥ 1000 用整股最低手續費，否則用零股最低手續費（規格 3.2 原文）。像 1500 股這種「整股＋零股」混合的一筆，實務上券商會拆成兩張單，這裡照規格當成一筆整股算。未實現損益的預估賣出費用也照同一規則，以全部持股當一筆算。
4. **已存交易的手續費與證交稅不重算**：計算持股時用交易上存的 `fee`、`tax`（M-09：改設定不回頭改舊交易）。只有「預估賣出費用」用目前的設定與證交稅率即時計算。
5. **股票股利在除權息日當天、所有交易之前套用**（實作指南）。同一天的交易依 `createdAt` 排序。
6. **除權息日當下沒有持股的股票股利視為錯誤**，`validateLedgerChange` 會拒絕：零成本的股數會讓平均成本與報酬率失真，通常是日期記錯。現金股利不檢查持股（只加總報酬）。
7. **只計入 `status = received` 的股利**；`estimated` 是 Phase 2 預留。
8. **已出清（持股 0）的證券**：市值與未實現損益是 0（不是「沒有值」），總報酬照算，就算沒有價格也一樣；平均成本與持有天數是「沒有值」。
9. **持有中但沒有價格**：該檔的市值、未實現損益、總報酬、報酬率都是 `null`。加總時，市值與未實現損益**不計入**這檔（規格第 5 章），並回報 `missingPriceCount`；但該組的**總報酬與報酬率改成 `null`**，因為少算一檔的市值會讓報酬看起來像虧錢。畫面顯示 —，並提示「有 N 檔持股缺少價格」。**待 PO 確認**。
10. **持有天數**＝今天 − 這一段持有的第一筆買入日（日曆天）。當天買入是 0 天。「今天」由呼叫端傳入，方便測試。
11. **累計投入**包含已出清那幾段的買入（規格第 2 章「所有買入交易」），所以賣光再買的證券，報酬率分母會累積。
12. **重播資料本身有錯**（例如還原了一份賣超的備份）時，`computePosition` 會丟錯而不是默默把股數算成負的；儲存層讀檔與還原時要先用 `validateLedger` 檢查（Story 008、014）。
13. **證券類型**先在 `ledgerTypes.ts` 自己定義 `SecurityType = "stock" | "etf"`，`computePosition` 用參數接收 `type` 與 `taxRate`，不依賴 Story 007 正在改的 `StockInfo`；Story 007 合併後由呼叫端從 `StockInfo` 帶入。
14. 舊的 `pnl.ts`、`compare.ts` 先不刪，Story 011 換掉首頁時再移除。
15. **一次變更只處理一筆**：`validateLedgerChange` 的刪除一次刪一筆（畫面上每次刪除都要二次確認）。M-02「刪除步驟 1 和 2」解讀成依序刪除，第二次被拒絕。
16. **錯誤訊息分兩種**：出問題的是正在輸入或修改的那一筆，直接說原因（「賣出股數超過持有股數（1,500 股）」）；是別筆紀錄被連帶影響，就說出那一筆的日期與股數，讓使用者知道要去改哪一筆。
17. `validateLedgerChange` 也做欄位檢查（成交價、股數、日期、手續費與稅不為負、買入沒有證交稅、股利金額與股數），「今天」由呼叫端傳入。
