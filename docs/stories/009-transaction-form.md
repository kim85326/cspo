# Story 009：新增／編輯／刪除交易

**身為** 想知道自己真正賺多少的投資人
**我想要** 把每一筆買賣（包含同一檔的多次買入）都記下來，手續費與證交稅自動算好、也能改成對帳單上的數字
**以便** App 用正確的成本算出我的持股與已實現損益

對應規格：[product-spec.md](../product-spec.md) 的 M-01（點選證券進入新增交易）、M-02 與 3.2、3.3、3.7；實作指南 [T4](../mvp-implementation-guide.md)。名詞見 [glossary.md](../glossary.md)。

## 路由

| 路由 | 畫面 | 誰會連過來 |
|---|---|---|
| `/transaction/new` | 新增交易 | 首頁、持股列表的「新增交易」（T6、T5） |
| `/transaction/new?symbol=2330` | 新增交易，證券已選好 | 單一持股頁（T5）、搜尋結果（M-01） |
| `/transaction/<id>` | 編輯或刪除這筆交易，`id` 是 `Transaction.id` | 單一持股頁的交易紀錄（T5） |

用法：`router.push("/transaction/new?symbol=2330")`、`router.push(\`/transaction/${tx.id}\`)`，或 `<Link href=…>`。
存檔或刪除後回上一頁；沒有上一頁（直接打開網址）就回首頁 `/`。畫面本體在 `src/screens/TransactionFormScreen.tsx`。

以 product-spec 3.7 的設定為準：手續費率 0.001425、無折扣、整股最低 20 元、零股最低 1 元；2330 是個股（證交稅 0.3%）。

## 決策紀錄

規格沒寫到、或需要選做法的地方。原則：選最不會讓使用者算錯錢的做法。

1. **「儲存並繼續新增」只保留證券，買賣回到「買入」、日期回到今天。** 規格寫「證券欄位保留，其他欄位清空」，買賣與日期也算其他欄位。保留「賣出」可能讓下一筆買入被誤記成賣出，回到預設比較安全。**待 PO 確認**：如果常見情境是同一天連續記很多筆，保留日期可能比較順手。
2. **手續費、證交稅分開記「手動改過」。** 規格說改過手續費或稅之後不再覆蓋「使用者的數字」：只改了證交稅（例如債券 ETF 免稅），手續費還是使用者沒碰過的自動值，應該繼續跟著價格與股數重算。存檔時 `Transaction.feeOverridden` 是兩者任一改過；重新打開時兩個都當成改過（只有一個欄位，不知道是哪個），不會偷偷改掉使用者的數字。
3. **「重新計算」把手續費與證交稅一起改回自動。** 只有一顆按鈕，比較好懂。
4. **買入時不顯示證交稅欄位**，存檔一律 0（規格 3.2 只有賣出才收；T1 驗證也會擋買入有稅）。從賣出切回買入再切回賣出，使用者手動改過的稅會保留。
5. **刪除的二次確認用畫面上的確認區塊**，不用系統對話框：React Native 的 `Alert` 在網頁版不會顯示按鈕，而測試同學有人用網頁版。確認文字寫出日期、買賣、證券、股數，避免刪錯筆。
6. **錯誤訊息放哪裡**：這一筆自己的問題（欄位不合法、這筆賣出賣超）標在欄位下方；連帶讓別筆賣超、存檔失敗顯示在「儲存」上方，文字沿用 T1 的 `validateLedgerChange`，會說出是哪一天賣出幾股的那筆。
7. **新增時在證券下方顯示「目前持有 N 股・平均成本 X」**（規格沒寫）。賣出前知道還有多少可以賣，也讓「繼續新增」之後看得到持股有沒有算對；Maestro 流程用它檢查持股數字。持股頁要等 T5，不在這張做。編輯時不顯示（會把正在編輯的那筆算進去，容易誤會）。
8. **預估總金額的標籤**：買入「預估付出總金額」、賣出「預估拿回總金額」，比單寫「預估總金額」清楚錢是出去還是進來。
9. **股票清單載不到時**（離線且沒快取）：編輯模式用代號頂著（名稱顯示代號、類型依代號判斷），照樣可以改與刪；新增模式的選擇器沒有清單可選，要重新打開畫面、等清單載到才能選。
10. **舊版轉入、日期不明的交易**：日期欄位提示補日期；使用者改了日期才拿掉 `tradeDateUnknown`，沒改就照存（Story 008 決策 2、3）。
11. **沒有放在功能開關後面。** 這兩個路由目前沒有任何入口（首頁、持股頁的連結由 T5、T6 加），測試同學的 APK 看不到。
12. **手續費使用記帳本的 `settings`**（Tech Day 不做 M-09 手續費設定，所以就是預設值）。

## 已知限制與需要注意

- **首頁（舊版 `CalculateScreen`）按「計算」會整份取代記帳本的交易**（Story 008 決策 14）：在這裡記的賣出，之後在舊首頁按「計算」就會被蓋掉。T6 換掉首頁並刪除 `ledgerHoldingStore` 之前，不要讓測試同學同時用這兩個畫面。T4 依分工不改首頁。
- 錯誤訊息裡的日期是 `2026-03-05`（T1 `validateLedgerChange` 的格式），畫面其他地方是 `2026/03/05`。
