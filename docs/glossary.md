# 共同語言（Glossary）

PO、測試、工程三方都用這份表上的詞。程式裡的名字對應右欄，看 code 時可以對照。

| 名詞 | 定義 | 程式裡的名字 |
|---|---|---|
| 股票代號 | 台股 4 到 6 碼數字，尾端可再帶一個英文字母，例如 2330、00878、00631L（槓桿 ETF）、2881A（特別股） | `symbol` |
| 股票名稱 | 公司或 ETF 的簡稱，例如 台積電 | `name` |
| 證券 | 一檔可交易的標的，分成「個股」或「ETF」，掛在「上市」或「上櫃」。程式裡沿用「股票」這個字（`StockInfo`），兩者指同一件事 | `StockInfo`（product-spec 的 Security） |
| 個股 | 單一公司的股票，例如 2330 台積電、5347 世界。選擇器上標「個股」；核心／衛星預設歸「衛星」，證交稅預設 0.3% | `type: "stock"` |
| ETF | 指數股票型基金，例如 0050、00878、006201、00679B（債券 ETF）。判斷規則：**代號 `00` 開頭就是 ETF**（簡化規則，ETN 與特別股會被當成個股，見 Story 007 決策紀錄）。選擇器上標「ETF」；預設歸「核心」，證交稅預設 0.1% | `type: "etf"` / `securityTypeOf` |
| 上市 | 在證交所（TWSE）掛牌交易，例如 2330、0050。行情來自證交所 OpenAPI | `market: "TWSE"` |
| 上櫃 | 在櫃買中心（TPEx）掛牌交易，例如 5347 世界、6488 環球晶、006201 元大富櫃50。行情來自櫃買中心 OpenAPI | `market: "TPEx"` |
| 股票清單 | 可以選的證券（代號、名稱、類型、市場）。app 裡是證交所 + 櫃買中心全市場（當天有成交的上市、上櫃股票與 ETF，約 2,300 檔），熱門清單排最前面、其餘依代號；測試用固定 45 檔。搜尋結果最多 20 筆 | `StockDirectory` |
| 買入價 | 每股買進價格 | `buyPrice` |
| 買入日期 | 哪一天買的，選填，格式 2026/10/05。有填才會在 K 線圖標出買入點；不能晚於今天 | `buyDate` |
| K 線（日 K） | 每個交易日一根 K 棒，畫出開盤、最高、最低、收盤。收盤高於開盤為紅 K，低於開盤為綠 K（台股慣例） | `Candle` / `CandleSource` |
| 歷史資料來源 | 給代號與期間、回每日 K 棒或除權息的地方。FinMind 為主（一檔一個請求就拿到好幾年，上市、上櫃、ETF 都有），失敗（斷網、超過每小時 300 次、週日維護）自動改問證交所／櫃買中心；抓過的月份存在手機裡，之後只補新的。自動化測試用固定假資料。見 Story 019 | `candleSource`、`corporateActionSource` |
| 除權息 | 公司配發股利：配現金叫「除息」、配股票叫「除權」。**除權息交易日**（除息日）當天或之後才買的股數不參與這次配發。現金股利以「每股幾元」、股票股利以「每千股配幾股」表示；**發放日**是現金入帳的日子（只有 FinMind 有）。ETF 常先公告除息日、幾天後才公告金額，這段期間金額顯示為待公告 | `DividendEvent`（`exDate`、`cashPerShare`、`stockPerThousand`、`payDate`） |
| 分割 | 1 股拆成好幾股、價格同比例下降，例如 0050 在 2025-06-18 一拆四。反分割、面額變更也算 | `SplitEvent`（`ratio`） |
| 還原收盤價 | 把之後的除權息與分割折算回去的收盤價，用來比較「含息」報酬。算法：除權息日之前的每一天乘上「參考價 ÷ 除權息前收盤價」，分割日之前的每一天除以分割比例；最新一天等於實際收盤價 | `adjustCloses` / `adjClose` |
| 基準標的 | 對決 B 拿來比的 ETF：0050（預設）或 006208 | `BenchmarkSymbol` |
| 如果改買 0050（對決 B） | 把每一筆實際買賣的金額，假設同一天改成買賣基準（用還原收盤價、可為小數單位、不算交易成本），和實際的「市值 + 領到的現金股利」比。期間不是「全部」時，期初持股市值當成第一筆投入（Story 022） | `buildBenchmarkDuel` |
| 交易日 | 有開盤的日子。不另外抓休市日曆：基準標的（例如 0050）有收盤價的日子就是交易日 | `tradingDayOnOrAfter`、`tradingDayBefore` |
| 買入點 | K 線圖上買入日期那根 K 棒下方的深藍 ▲。買入日是假日就標在下一個交易日 | `locateBuyDate` / `buyPoint` |
| 成本線 | K 線圖上買入價那條金色水平虛線 | `costPrice` |
| 數量 | 股數。1 張 = 1000 股。第一版以「股」為單位 | `shares` |
| 現價 | 最近一筆成交價或收盤價 | `currentPrice` / `Quote.price` |
| 持股 | 某檔證券目前持有的狀態，由交易與股利**計算**出來，不直接輸入。（舊版首頁的「持股」是一筆代號 + 買入價 + 數量，Story 011 換掉首頁後移除） | `Position`（舊版 `Holding`） |
| 持有成本 | 目前持有股數對應的成本，**含買入手續費**。賣出時依平均成本扣掉賣出的部分。（舊版首頁的「買入成本」= 買入價 × 數量，不含手續費） | `Position.costBasis`（舊版 `cost`） |
| 市值 | 參考價 × 持有股數（舊稱「現值」，定義相同） | `marketValue` |
| 盈虧 | 拆成「已實現損益」與「未實現損益」，加上股利成為「總報酬」。（舊版首頁的盈虧 = 現值 − 買入成本，Story 011 後不再使用） | 舊版 `pnl` |
| 報酬率 | 盈虧 ÷ 買入成本 | `returnRate` |
| 行情來源 | 給代號回現價的地方。app 裡把證交所（上市）與櫃買中心（上櫃）的 OpenAPI「每日收盤行情」合成一個來源（最近一個交易日收盤價，一次拿全市場，5 分鐘內不重抓）；一邊拿不到時另一邊照用。自動化測試與 `EXPO_PUBLIC_USE_FAKE_PRICES=1` 時用固定假價 | `PriceSource`（`marketSource` = `twseSource` + `tpexSource` / `fakePriceSource`） |
| 資料日期 | 現價是哪一個交易日的收盤價，結果卡上顯示「收盤價 2026/10/22」。假價沒有這欄 | `Quote.asOf` |
| 行情載入失敗 | 斷網或證交所、櫃買中心都沒回應，畫面顯示「行情載入失敗，請檢查網路後重試」，再按「計算」會重試。只有一邊沒回應時，查不到的代號也顯示這句，不顯示「找不到這檔股票」 | `PriceLoadError` |
| 免責聲明 | product-spec M-10 那段文字：「本 App 僅供記帳與計算參考，不構成任何投資建議……請以券商資料為準。」第一次開 app 要按「我已了解並同意」才能用，之後在「設定」頁隨時看得到（Story 013） | `DISCLAIMER_TEXT` / `DisclaimerGate` |
| 幣別、匯率 | 每筆交易、股利記錄的幣別（`TWD`／`USD`）與成交當下的匯率（1 美元 = 多少台幣）。所有報酬都換成台幣算：每筆用自己的匯率，市值用今天的匯率。Tech Day 期間全部是台幣、匯率 1，畫面不顯示；沒填的舊資料視為台幣（Story 029） | `Currency` / `fxRate` / `toTwd` |
| 定期定額 | 每月固定日期、固定金額買同一檔。規則設好後，App 開啟時用扣款日（遇假日順延）的收盤價自動記上買入交易，`source = dca`，列表標示「定期定額」。同一規則同一期只產生一次，刪掉也不補回（Story 024） | `DcaRule` / `generateDcaTransactions` / `runDcaCatchUp` |
| Free／Pro | 兩種方案。Pro 功能：年化報酬率、個股 vs ETF 對決（完整）、股利自動帶入、定期定額自動記帳（不限條數）、資產走勢與配置（全部期間）。Tech Day 只做畫面，按「升級 Pro」只顯示「Pro 方案即將推出」（Story 020） | `PRO_FEATURES` / `isPro` |
| Demo 開關 | 設定頁底部的「Demo：解鎖所有 Pro 功能」，打開後所有 Pro 功能解鎖，只為了展示，不會收費；重開 app 仍維持 | `demoUnlocked` |
| 比較 | 舊版首頁的功能：兩檔以上的持股一起算，依報酬率排名；第一名標「表現最好」、最後一名標「表現最差」。之後由持股明細的排序取代（Story 010、011） | `compareHoldings` / `ComparisonResult` |
| 排名 | 比較結果裡的名次，從 1 開始。報酬率高者在前；相同則盈虧金額大者在前；再相同照輸入順序 | `ComparisonRow.rank` |
| 合計 | 所有持股的成本、現值、盈虧相加；總報酬率 = 總盈虧 ÷ 總成本（不是各檔報酬率平均） | `ComparisonResult.total` |
| 已儲存的持股 | 快速試算（舊版首頁）的欄位內容（代號、買入價、數量、買入日期的原始字串）。舊版存在 `cspo.holdings.v1`；Story 011 起快速試算存自己的 `cspo.quickCalc.v1`，第一次打開用記帳本的買入交易當初始值 | `SavedHolding` |
| 持股儲存 | 快速試算讀寫「已儲存的持股」的介面。Story 011 起只讀記帳本、不寫記帳本（`createQuickCalcHoldingStore`） | `HoldingStore` |
| 首頁總覽 | 打開 app 的第一頁：整體、核心（ETF）、衛星（個股）三組的累計投入、目前市值、總報酬與報酬率、已實現、未實現、已領股利，下面列市值最大的 5 檔持股。沒有交易時顯示「新增第一筆交易」（Story 011） | `HomeScreen` / `buildOverview` |
| 快速試算 | 舊版首頁（輸入代號、買入價、數量直接算盈虧、多檔比較、K 線、AI 解讀），不記帳。Story 011 起搬到 `/calculate`，從首頁底部進去；要不要拿掉待 PO 決定 | `CalculateScreen` |
| 價格日期 | 首頁上方的「價格：2026/10/22 收盤價」。各檔日期不同時取最舊的一天 | `oldestPriceDate` |
| 交易 | 一筆買入或賣出：代號、日期、成交價、股數、手續費、證交稅。持股由交易重算出來 | `Transaction` |
| 股利 | 現金股利（實際入帳金額）或股票股利（配發股數） | `Dividend` |
| 記帳本 | 全部交易、股利、持股設定與手續費設定，存在手機本機（`cspo.ledger.v1`）的就是這一份 | `Ledger` / `LedgerStore` |
| 資料搬移 | 升級後第一次開 App，把舊版存的持股每筆轉成一筆買入交易（備註「由舊版資料轉入」），新記帳本寫入並確認後才刪舊資料；搬過就不再搬（Story 008） | `migrateLegacyHoldings` / `migrateSavedHoldings` |
| 日期不明 | 搬過來的交易沒有可用的買入日期（舊版沒填或認不出來），交易日期暫用搬移當天；持有天數與年化報酬率在補上日期前不準 | `Transaction.tradeDateUnknown` |
| 預估總金額 | 新增交易時即時顯示：買入 = 成交金額 + 手續費（預估付出）；賣出 = 成交金額 − 手續費 − 證交稅（預估拿回）。用欄位上的手續費與稅，使用者改過就用改過的（Story 009） | `estimatedTotal` |
| 手動覆寫 | 使用者把自動帶入的手續費或證交稅改成對帳單上的數字。改過的欄位之後改價格、股數都不再自動覆蓋，按「重新計算」才改回自動（Story 009） | `Transaction.feeOverridden` |
| 儲存並繼續新增 | 新增交易存檔後留在表單，證券保留、其他欄位回到預設，直接輸入下一筆（Story 009） | `TransactionFormScreen` |
| 證券類型 | 個股或 ETF，決定預設證交稅率與核心／衛星 | `SecurityType`（`stock` / `etf`） |
| 手續費 | max(floor(成交金額 × 0.001425 × 折扣), 最低手續費)。最低手續費：1000 股以上 20 元、零股 1 元，都可在設定改。自動帶入，可手動改成對帳單上的數字 | `calcFee` / `UserSettings` |
| 證交稅 | 只有賣出才收：floor(成交金額 × 證交稅率)，個股 0.3%、ETF 0.1% | `calcTax` / `defaultTaxRate` |
| 平均成本 | 持有成本 ÷ 持有股數。賣出不改變平均成本；股票股利會讓它下降；賣光再買重新算 | `Position.averageCost` |
| 已實現損益 | 已賣出部分的損益：賣出淨額（金額 − 手續費 − 證交稅）− 平均成本 × 賣出股數 | `Position.realizedPnl` |
| 未實現損益 | 還沒賣的部分如果用參考價全部賣掉的預估損益：市值 − 預估賣出手續費與證交稅 − 持有成本 | `Position.unrealizedPnl` |
| 總報酬 | 已實現損益 ＋ 未實現損益 ＋ 已領現金股利 | `Position.totalReturn` |
| 累計投入 | 所有買入的成交金額加手續費（含已經賣光的那幾段） | `Position.invested` |
| 簡單報酬率 | 總報酬 ÷ 累計投入；累計投入為 0 時顯示 — | `returnRate` / `simpleReturnRate` |
| 持有天數 | 從這一段持有的第一筆買入日算到今天；賣光再買就從新的第一筆算 | `Position.holdingDays` |
| 核心／衛星 | 核心部位預設是全部 ETF，衛星部位預設是全部個股；使用者可以逐檔切換 | `Bucket`（`core` / `satellite`）/ `HoldingSetting` |
| 持股明細 | 每一檔的持股數字：股數、平均成本、參考價、市值、未實現、已實現、股利、總報酬與報酬率、持有天數。分「持有中」與「已出清」兩頁，可依市值、報酬率、總報酬排序（Story 010） | `HoldingView` / `HoldingRow` / `useHoldings` |
| 已出清 | 曾經買過、現在股數是 0 的證券。只顯示已實現損益與股利 | `closedHoldings` |
| 未實現報酬率 | 未實現損益 ÷ 持有成本，持股明細「未實現損益」括號裡的 %。和總報酬率（÷ 累計投入）不同 | `unrealizedRate` |
| 整體／核心／衛星加總 | 三組各自的累計投入、市值、已實現、未實現、股利、總報酬。有持股缺少價格時，市值與未實現不算那一檔，總報酬顯示 — | `summarize` / `GroupSummary` |
| 年化報酬率（XIRR） | 把每一筆買入、賣出、現金股利和今天的期末價值（市值 − 預估賣出費用）當成現金流，算出相當於每年賺幾 %。第一筆現金流距今不到 365 天時不顯示，改顯示「持有未滿一年」；算不出來顯示 — | `xirr` / `positionAnnualizedReturn` / `portfolioAnnualizedReturns` / `AnnualizedReturn` |
| 資產配置 | 持有中的持股依目前市值分成幾塊：核心／衛星、個股／ETF、每一檔各占多少 %。缺價格的不算進去，另外提示檔數 | `computeAllocation` / `Allocation` |
| 功能開關 | 開發中的功能先藏起來，預設關閉。可以遠端切換：`node scripts/feature-flags.mjs set <名稱> on`（或 `off`）改 GitHub `feature-flags` 分支的 JSON，已裝好的 APK 最多 5 分鐘後、回到前景就套用；工程同學也能用 `.env.local` 的環境變數在自己的 dev server 打開（蓋過遠端）。只控制畫面看不看得到，不是保護。例如「從截圖匯入」、「AI 解讀」、「Pro 方案」 | `useFeatures` / `FeatureFlagsProvider`（`src/hooks/useFeatures.tsx`）、`FEATURE_NAMES`（`src/config/features.ts`） |
| 截圖匯入 | 把券商 app 的持股畫面截圖（從相簿選或現場拍）交給 AI 辨識，自動填進持股欄位。辨識結果一定要人工核對 | `useScreenshotImport` / `applyExtraction` |
| 辨識結果 | AI 從截圖讀出的每一檔：代號、名稱、成本價、數量（股或張）與信心；還沒對到股票清單、還沒驗證 | `ExtractedHolding` / `ExtractionResult` |
| 辨識信心 | AI 對一檔持股看得清不清楚：high 或 low。low、或對不到股票清單的欄位，標籤旁顯示「請確認」 | `ExtractionConfidence` / `ReviewFlags` |
| 辨識服務 | 收截圖、回辨識結果的地方。手機不直接呼叫 AI，而是送到工程同學電腦上的後端 `backend/` 的 `/recognize`（和 AI 解讀同一台），由後端用 API key 呼叫 Claude | `HoldingRecognizer` / `backend/src/claudeRecognize.ts` |
| AI 解讀 | 算完盈虧後按「AI 解讀」，由 AI 用白話說明這組持股目前的表現：一句話總結、2～4 點觀察、一句風險提醒。只描述數字，不給投資建議 | `InsightSection` / `InsightCard` / `Insight` |
| AI 解讀後端 | 跑在工程同學電腦上的小服務（`backend/`，`npm run backend` 啟動）。手機把持股數字送過去，它用電腦上的 API key 呼叫 Claude。API key 不會離開那台電腦 | `backend/` / `InsightProvider`（`backendInsightProvider`） |
| 解讀輸入 | 送給 AI 解讀後端的資料：股票代號、名稱、股數、平均成本、成本、現價、盈虧、報酬率與合計。沒有任何個人資料 | `InsightInput`（`src/domain/insightInput.ts`） |
| 存取碼（AI 解讀） | app 呼叫 AI 解讀後端時帶的共享密碼。會被打包進 app，所以只能擋路人，不是真正的秘密 | `EXPO_PUBLIC_INSIGHT_ACCESS_TOKEN` / `INSIGHT_ACCESS_TOKEN` |
| 對外公開（AI 解讀） | 用 `npm run backend:tunnel` 透過 ngrok 讓其他網路的手機連到工程同學電腦上的後端。ngrok 免費帳號給一個固定網址（`xxxx.ngrok-free.app`），設進 app 一次就好；Ctrl+C 關掉後別人就連不到 | `backend/src/tunnel.ts` / `EXPO_PUBLIC_INSIGHT_API_URL` |
| 每日上限（AI 解讀） | 後端每天最多呼叫 AI 幾次（所有人合計，預設 100），超過顯示「今天的 AI 解讀次數已達上限」 | `INSIGHT_DAILY_LIMIT` |

## 顯示慣例

- 台股漲紅跌綠，跟美股相反。
- 盈虧金額顯示到整數，千分位逗號，正數帶 `+`。
- 報酬率顯示兩位小數百分比。

## 顯示慣例（截圖匯入）

- 截圖裡寫「張」的數量一律換算成股（1 張 = 1000 股）。
- 同一檔出現兩次會合併：股數相加、成本價取加權平均，並提示已合併。
- 空白的持股欄位會被辨識結果覆蓋；使用者已經填的保留在原位，辨識結果接在後面；總數仍然最多 5 檔。

## 顯示慣例（AI 解讀）

- 解讀卡固定附「僅為數據解讀，不構成投資建議」。
- 解讀不存檔；重新按「計算」後舊的解讀消失，要再按一次。
- 錯誤（後端沒開、連不到、沒設 key、太頻繁）顯示原因，按鈕變成「重試 AI 解讀」，盈虧結果保留。

## 顯示慣例（比較）

- 比較一次最多 5 檔。
- 排名看報酬率，不看盈虧金額：投入金額不同時，金額大的不一定表現好。
